# IBM Concert Plugin v1.2.4 - IT Asset Schema Fix

## Problem Summary

**Issue**: IT assets were not appearing in GCM UI despite:
- Playbooks successfully creating IT asset files (`it_asset_details_*.json`)
- Files being included in GCM transformation processing
- No transformation errors reported

**Root Cause**: The IT asset transformation was using an incorrect schema that mixed crypto object fields with IT asset fields.

## Technical Analysis

### What Was Wrong

The IT asset transformation in v1.2.3 incorrectly used:

```json
{
  "category": {"const": "IT_ASSET"},      // ❌ WRONG - IT assets don't use category
  "asset_type": {"const": "IT_ASSET"},    // ❌ WRONG - Should be descriptive type
  "uri": {...}
}
```

### Why This Failed

According to GCM documentation (`.bob/rules/transformation.md`):

1. **IT Assets Don't Use `category` Field**
   - The `category` field is ONLY for crypto objects (CRYPTO_OBJECT)
   - IT assets have a flat structure without category classification

2. **`asset_type` Should Be Descriptive**
   - For IT assets, `asset_type` should describe the asset (e.g., "APPLICATION", "SERVER", "DATABASE")
   - Using "IT_ASSET" as the type is incorrect - that's the category name, not a type

3. **GCM IT Asset Schema**
   ```json
   {
     "uri": "required-field",           // ✅ Mandatory
     "hostname": "optional",            // ✅ Optional
     "ip": "optional",                  // ✅ Optional
     "port": 443,                       // ✅ Optional
     "protocol": "HTTPS",               // ✅ Optional
     "asset_type": "APPLICATION",       // ✅ Optional - descriptive type
     "discovery_sources": ["profile"]   // ✅ Optional
   }
   ```

## Solution Implemented

### Changes Made in v1.2.4

**File**: `transformation/discovery/transform_discover.json`

1. **Removed `category` field** - IT assets don't use this
2. **Changed `asset_type`** from `"IT_ASSET"` to `"APPLICATION"`
3. **Added `description` field** with Concert context:
   ```json
   "description": {
     "custom_func": {
       "name": "concat",
       "args": [
         {"const": "IBM Concert Access Point - "},
         {"xpath": "name"},
         {"const": " (Environment: "},
         {"xpath": "environment_name"},
         {"const": ")"}
       ]
     }
   }
   ```
4. **Improved metadata naming** - All Concert fields now prefixed with `concert_`

### Corrected IT Asset Transformation

```json
{
  "format": "json",
  "yields": "it-asset",
  "transformation": {
    "parser_settings": {
      "file_format_type": "json",
      "version": "omni.2.1"
    },
    "transform_declarations": {
      "FINAL_OUTPUT": {
        "xpath": ".",
        "object": {
          "uri": {"xpath": "host"},                    // ✅ Mandatory field
          "hostname": {...},                           // ✅ Extracted from URL
          "protocol": {...},                           // ✅ Extracted from URL
          "port": {...},                               // ✅ Extracted from URL
          "asset_type": {"const": "APPLICATION"},      // ✅ Descriptive type
          "description": {...},                        // ✅ Concert context
          "discovery_sources": [...],                  // ✅ Profile tracking
          "metadata": {                                // ✅ Concert metadata
            "concert_access_point_id": {...},
            "concert_application_name": {...},
            "concert_environment_name": {...},
            ...
          }
        }
      }
    }
  }
}
```

## Expected Results

After deploying v1.2.4, IT assets should:

1. ✅ **Appear in GCM UI** - IT Assets section
2. ✅ **Show correct asset type** - "APPLICATION"
3. ✅ **Display descriptions** - "IBM Concert Access Point - {name} (Environment: {env})"
4. ✅ **Include all metadata** - Application, environment, endpoints from Concert
5. ✅ **Link to certificates** - Via relationships array in certificate transformation

## Deployment Steps

### 1. Package Plugin

```bash
# Linux/macOS
./package.sh

# Windows PowerShell
.\package.ps1
```

This creates: `ibm-concert-discovery-1.2.4.zip`

### 2. Upload to GCM

Use the GCM UI or API to upload the new plugin version.

### 3. Update Existing Integration

If you have an existing IBM Concert integration:
1. Navigate to the integration in GCM
2. Update to plugin version 1.2.4
3. Run a new discovery

### 4. Verify IT Assets

After discovery completes:
1. Navigate to GCM UI → IT Assets
2. Filter by discovery source (your Concert integration profile)
3. Verify assets appear with:
   - Asset Type: APPLICATION
   - Description: IBM Concert Access Point - {name} (Environment: {env})
   - Metadata: Concert application and environment details

## Troubleshooting

### IT Assets Still Not Appearing

1. **Check Discovery Logs**
   - Verify IT asset files are being created
   - Check file naming: `it_asset_details_*.json`

2. **Check Transformation Logs**
   - Look for transformation errors
   - Verify `yields: "it-asset"` is recognized

3. **Verify File Content**
   - IT asset files should have `host` field
   - `host` should be a valid URL or hostname:port

### Assets Appear But Missing Data

1. **Check Metadata**
   - Verify Concert API returns all expected fields
   - Check playbook variable mapping

2. **Check Transformation**
   - Verify XPath expressions match actual data structure
   - Test JavaScript functions with actual data
